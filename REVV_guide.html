완료된 기능

와인딩 곡률 분석 엔진
bearing rate 기반 커브 분석 + curveRatio×√dist 밀도 점수 산출. 반경 30/50/100km 선택 가능.
route_service.dart
OBD2 BLE 완전 연동
ELM327 자동 감지, RPM/냉각수/스로틀/연료 등 14개 PID 200ms 폴링. 채널 커스터마이징까지 완성.
obd_service.dart
Mapbox 커스텀 다크 스타일
"REVV Waze Neon v3" 스타일 적용 완료. 스프린트 모드 시 navigation-night-v1으로 자동 전환.
mapbox_service.dart
스프린트 모드 + 런카드
주행 시작 → GPS 실시간 수집 → 종료 → 런카드 자동 저장. 날씨/거리/시간/최고속도 기록. 같은 루트 N회차 표시.
sprint_screen / run_card_screen
IMU G포스 측정 서비스
50Hz 가속도+자이로, 4가지 마운트 타입 캘리브레이션, lateralG/longitudinalG/yawRate 계산 완성.
imu_service.dart
여정 플래너 (POI → 귀가)
카테고리 선택 → Overpass POI 검색 → Google Maps 경유지+귀가 연결.
trip_planner_screen
DrivingContextService — WINDING / SPORT 감지
GPS bearing rate 기반 windingIntensity + OBD RPM/속도 비율 → DriveMode(cruise/winding/sport) 자동 추론. 스프린트 화면 테두리·뱃지 반응.
driving_context_service.dart
경유지 TSP 최적화 (WaypointOptimizer)
특정 와인딩 코스를 반드시 통과하는 Nearest-Neighbor + 2-opt 알고리즘. 정/역방향 자동 선택, Mapbox 25점 제한 균등 샘플링.
waypoint_optimizer.dart
앱 내 통합 내비게이션 (nav polyline)
외부 앱 없이 REVV 안에서 현재위치→루트시작점 Mapbox 경로 자동 fetch. 200m 이내 루트 진입 자동 감지 → navPolyline 해제 + 배너 표시.
sprint_screen / directions_service
런 히스토리 화면 (history_screen.dart)
RunHistoryService.runs 리스트 기반 과거 런 목록 UI. 통계 바(총 거리/횟수/시간), 런 타일, 코너 브라켓 디자인, 빈 상태 화면 완성. 클라우드 싱크 배지 포함.
history_screen.dart
런카드 공유 이미지 (screenshot + share_plus)
RepaintBoundary + RenderRepaintBoundary.toImage(pixelRatio:3) → PNG → SharePlus.instance.share(ShareParams). 공유 중 버튼 상태 처리.
run_card_screen.dart
JARVIS 주행 후 자동 분석 리포트
런 종료 시 RevvAiService.analyzeRun(session) 자동 호출. Claude Haiku API, 루트명/거리/G포스/DriveMode 비율 전달. 3문장 한국어 분석. 폴백 로컬 로직 포함.
revv_ai_service.dart
RunSession G포스 + DriveMode 기록
maxLateralG / maxLonG (ImuService 50Hz 세션 최댓값), driveModeSeconds (cruise/winding/sport 체류 시간) RunSession 모델에 추가. SprintScreen에서 수집 후 stopSession()에 전달.

✅ 진짜 강점 (투자 근거가 될 수 있는 것)
1. 기술 조합이 유니크하다
OBD2 + IMU(50Hz) + 루트 발굴 + 주행 기록 일체형 — 이 조합을 하나의 앱에 담은 건 없다
Scenic = 지도만 / Rever = 커뮤니티만 / OBD 앱 = 차 데이터만. REVV는 세 개를 연결하는 유일한 앱
2. 데이터 flywheel의 씨앗이 이미 있다
RunSession에 maxLateralG가 저장됨. routeId와 연결만 하면 실주행 검증 루프가 완성
이게 쌓이면 "달려본 앱"이 되는 구조. 경쟁사가 뒤따라오기 어려운 데이터 해자
3. 캐나다 로컬 최적화 깊이가 있다
퀘벡 rang 직선 도로 패널티 / 로렌시안·아팔래치안 고도 보너스 — 글로벌 앱이 신경 안 쓰는 niche
로컬에서 먼저 "이건 REVV가 제일 잘 안다"는 신뢰를 얻을 수 있는 영역
❌ 솔직한 약점 (지금 당장 투자 못 하는 이유)
1. 유저가 1명이다. 그것도 만든 사람 본인
Product-Market Fit 검증이 전혀 없음. "내가 쓰고 싶어서 만들었다"는 아직 취미 프로젝트 단계
2. 핵심 기능이 실기기 테스트도 안 됐다
G포스, TBT, 코너 브리핑, 레드 플래시 — 이 앱의 정체성인 기능들이 검증 0. 빌드는 되지만 작동한다는 보장 없음
3. 루트 로직이 아직 경쟁사를 따라가는 중
Bearing rate + elevation = Kurviger가 3년 전에 한 것. 지금은 "따라잡기" 단계이지 앞서가는 단계가 아님
4. OBD 동글 없으면 앱의 절반이 안 된다
VEEPEAK 동글 필요 → 일반 사용자 진입 장벽 높음. "나 OBD 있어?" 라는 질문에 대부분 "없어"
5. 수익 모델 없다
Pro 구독 설계는 됐지만 구현 0. API 비용(Mapbox, Claude, Overpass)은 실사용자 늘어나면 바로 돈 나감
