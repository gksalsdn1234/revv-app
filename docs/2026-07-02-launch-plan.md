## 0. 북극성 (모든 결정의 기준)

> **REVV는 크루 드라이빙 앱이다. "혼자 달리게 두지 않는 앱."**

- 판단 기준 1: 이 작업이 주말 크루 드라이브를 더 좋게 하는가?
- 판단 기준 2: 이 작업이 3주 안의 출시를 앞당기는가? (No면 4장 아웃스코프로)

### 0.1 브랜드 철학 (2026-07-06 브레인스토밍 확정)

> **REVV는 새로운 기능을 만드는 회사가 아니라, 자동차를 가진 사람의 하루를 더 즐겁게 만드는 경험을 설계하는 회사다.** 그 경험은 새로운 것을 발명해서가 아니라, 이미 흩어져 있는 좋은 것들을 가장 자연스럽게 연결해서 만들어진다.

- **포지셔닝:** Google Maps는 목적지까지 가장 효율적으로 데려가는 회사, REVV는 목적지까지 가는 시간을 가장 즐겁게 만드는 회사. 내비와 경쟁하지 않고 보완한다 (Strava 모델 — 기존 기술 위에 경험을 만든다).
- **핵심 문장:** "목적지가 없어도, 목적지가 있어도, 드라이브를 더 재밌게 만든다." (생추천형 + 목적지 선택형 2모드의 근거)
- **브랜드 3단어:** Cars. Connection. Culture. (자동차를 좋아하는 사람들 · 사람/장소/코스의 연결 · 만들고 싶은 자동차 문화)
- **랜딩 카피 방향:** "차는 있지만, 어디 갈지 모르는 사람을 위해." — 웹은 기능 나열 금지, 철학 한 줄 + Download 버튼. 지금은 랜딩 페이지 수준이면 충분 (심장=앱 먼저).
- 브랜드의 중심은 **속도가 아니라 경험** (기존 안전 카피 원칙과 일치).

### 0.2 안 만드는 것 (REVV Bible)

- ❌ **내비게이션을 만들지 않는다** — Google Maps/Waze를 사용한다.
- ❌ **계기판 앱을 만들지 않는다** — OBD는 추천 품질 향상을 위한 수단이다.
- ❌ **모든 사람을 위한 여행 앱을 만들지 않는다** — 차를 가진 사람들의 드라이브 경험을 만든다.

## 2. 출시 후 로드맵 (3주 안에는 안 만든다 — 방향 고정용)

**버전 프레임 (2026-07-06 확정):** V1 = "오늘 어디 가지" + 좋은 루트 + 기록 → V2 = 커뮤니티/크루 → V3 = AI 개인화 + OBD → V4 = 스마트워치/하드웨어 확장. 아래 항목들은 이 프레임 안에 배치된다. 새 아이디어는 전부 이 프레임의 뒷번호(Season 2)로 보내고 V1을 끝낸다 — **이제 중요한 건 아이디어를 떠올리는 게 아니라, 떠오른 아이디어를 언제 만들지 결정하는 것.**

1. **크루 사다리:** 런카드 비교(코드 불필요, 크루 드라이브에서 전원 기록) → 루트 공유(+Apple 로그인) → 크루 세션(지도에 서로 위치) → 워키토키
   - **워키토키 스펙 확정 (2026-07-02, 검증된 고통):** 크루는 현재 인스타 통화로 주행 — 상시 연결이 문제(음악 죽음, 어색한 침묵, 배터리). 답은 통화가 아니라 **PTT + 오디오 더킹**: 음악 위에 필요할 때만 얹히는 무전. 핵심 기술 = 더킹이며, 음성 코너 브리핑과 **같은 오디오 레이어를 공유**(코파일럿 목소리 + 크루 무전이 한 채널 — "혼자 달리게 두지 않는 앱"의 소리적 완성형). 선발주자 Zello 존재(루트 문맥 없음 — REVV 차별화는 드라이빙 두뇌). 한국 정착 후 첫 크루 스프린트에서 루트 공유(가벼움) 출시 + PTT 더킹 프로토타입(무거움) 병행 검증.
   - **몬트리올 운영 (지부장 없음 확정):** 성장 시장이 아니라 자동 항해 + 데이터 농장. 원격 SNS 성장 시도 금지(한국 구축과 에너지 충돌). 출시 후 사용 데이터로 최다 사용 크루원이 드러나면 그때 자연 발생 지부장으로 위임 — 지명하지 말고 관찰.
2. **Drive Duration Planner (2막 간판):** 출발지→목적지에 와인딩 시간 예산 배분. v1=목적지+예산 1개→경로 1개 / v2=시간 옵션 비교 / v3=도착시간 역산+휴식 포함. 차별화 핵심은 시간 예산+역산(강도 3옵션은 Kurviger 선례 있음). 롱라이드 체인 빌더는 이 기능의 부품으로 흡수 (`buildCompositeFallbackRoutes` 승격, main의 `fetchConnectingRoutes`/way stitching 이식)
3. **음성 코너 브리핑 (코파일럿 1호):** 놀랄 코너 3패턴만 — 긴 직선 뒤 급코너 / 감아 들어가는 코너(decreasing radius) / 연속 콤보. 장기적으로 크루 급브레이크 텔레메트리로 위험 코너 학습(고유 데이터 해자)
4. 시작점 자유(방향 반전 + 임의 지점 시작), 트랙데이 병행

2. 1.5~2시간 크루 드라이브 1회 (배터리·발열 측정 겸함, 시작/종료 배터리 % 기록)
3. 주행 중 각본: ① 5분 비행기 모드(LTE 음영) ② 전화 수신 1회 ③ 앱 백그라운드 전환 — 각 이벤트 후 기록 연속성 확인
4. 종료: 오프라인 상태로 런 저장 → 재연결 → pending upload queue 처리 확인
5. 동일 드라이브에서 스토어 스크린샷·영상 촬영 (홍보 자산 동시 확보)
6. 귀가 후: 불어 로케일 전 화면 1회전 (주행 불필요)

테스트 데이 2 (Week 2 주말)는 예비일 — 수정 반영된 릴리즈 후보 재검증. 데이 1이 깨끗하면 생략.

## 2.6 V1 데이터 전략 + 루트플래너 원칙 (2026-07-06 브레인스토밍 확정)

### V1 목표 재정의

> **V1의 목표는 좋은 앱이 아니라, REVV만이 가질 수 있는 데이터를 모으는 시작점이다.** 서버는 "루트를 보여주는 곳"이 아니라 REVV가 점점 똑똑해지는 기억장치. 코드는 다시 만들 수 있지만, 유저들이 쌓은 루트 평점·재방문·계절별 선호·취향 데이터는 다시 만들 수 없다 — 그게 해자다.

**출시 전 범위 잠금 (이 3개로 끝):**
1. **루트플래너 수정** — 생추천형 / 목적지 선택형 / 멍청한 우회 제거 / 기본 루트 vs REVV 루트 비교
2. **데이터베이스 셋업** — 학습 루프만 저장되게 (완벽한 DB 금지): `recommendation_logs` / `drive_sessions` / `route_feedback` / `telemetry_summary`(요약만 — 6.5장 데이터 최소화 원칙 그대로) / `user_preferences` 최소형
3. **출시** — 더 이상 기능 추가 금지

최소 학습 루프 = **추천했다 → 선택했다 → 달렸다 → 만족/불만 남겼다.** 이 4개만 저장되면 출시해도 된다. 출시 전에 개인화 UI/AI는 만들지 않는다 — 목표는 **Personalization-ready database**까지만. (개인화 계산은 나중에 단순 누적으로 시작: 선택 +1 / 완주 +2 / 좋아요 +3 / 재주행 +4 / 싫어요 −5. 싫어요 제거가 좋아요 찾기보다 효과적.)

### 추천 2모드 (제품 구조)

- **생추천형** — "오늘 어디 가지?": 출발지+가능 시간+혼자·크루+분위기 → 루트 밀도 높은 방향 먼저 선택 → 루트 클러스터 체인 → corridor 안에서만 POI. 라이트 유저 입구.
- **목적지 선택형** — "가는 김에 재밌게": 기본 경로 → corridor 안 후보 필터링 → detour score → 상위 1~3개만 삽입. 헤비/실용 유저 입구. 목적지 여러 개면 **leg 단위 최적화** + 우회는 시간 예산 안에서만.

### 루트플래너 품질 원칙

- **좋은 파생루트 = 재미 증가량 ÷ 추가 시간.** 목적지 방향을 망치는 후보는 재미 점수 무관 탈락. 진입점/복귀점 자연스러움이 최우선 필터 — 루트를 통째로 붙이지 말고 "재밌는 도로 조각"으로 쓴다.
- **납득 가능한 우회로 보여준다:** "기본 1시간 12분 / REVV 1시간 48분 (+36분) — 커브 72개, 호수뷰, 신호 적음" 식. 사용자가 "이 정도 돌아가는 건 인정"하게 만드는 게 핵심.
- **엔진은 하나, 가중치가 여러 개:** curve/elevation/road_width/lake/forest/viewpoint 등 feature는 공유, 모드(Driving/Scenic/Night/Chill)별 weight만 다르게. 새 모드 = 새 엔진이 아니라 가중치 추가. `route_scores`도 단일 점수가 아니라 winding/scenic/night_view/photo/chill/safety_stop 분리로 확장 (V3 개인화·AI의 기반).

### API 비용 아키텍처

> **비싼 API는 사용자가 진짜 의사결정하는 순간에만.** 잘못 짜면 수익화 전에 API 비용으로 먼저 죽는다.

```
Route Engine(로컬, 뇌) → POI 캐시(기억, tile 단위 TTL) → 부족할 때만 Places →
AI 큐레이터(마지막, 설명/조합만 — 검색 금지) → Google Maps/Waze 핸드오프(내비 기사) → 기록 저장(Supabase)
```

- 앱 첫 화면에서 AI/Places/전체 루트 계산 금지 — 위치+캐시+날씨 요약만.
- Directions 재검증은 상위 후보 3~5개만. AI 입력은 이미 걸러진 후보 (환각/비용/속도 모두 이유).
- 외부 내비 핸드오프는 entry point + key waypoint 1~2개 + exit + destination만 전달.

## 7. 아이디어 주차장 (출시 후 검토)

- **AI 드라이빙 코치 (2026-07-02, 민우 원안 — 2막 심화 + 수익화 1순위 후보):** 런카드에서 주행 후 코칭 리뷰. 규칙 ① '빠름'이 아니라 '잘 다룸'(부드러움·라인 일관성·브레이킹 타이밍)만 지적 — 안전 언어와 좋은 코칭이 일치 ② 모든 문장은 텔레메트리 인용 필수(일반론 금지) ③ 종단 비교("지난주보다 브레이킹 부드러워짐")가 리텐션 훅. 재료는 현 WIP의 이벤트 분석(급브레이크/급가속/와인딩 샘플)이 그대로. 실시간 지적 금지(그건 음성 브리핑 영역). 지역 커버리지 불필요 → 한국 이주 직후 작업 후보. main의 revv_ai_service 참고.

- **드라이브 테마 추천 (2026-07-06, V2~V3 — 브랜드에 가장 맞는 방향):** 목적지가 아니라 **하루를 고른다** — 🌅 노을 드라이브 / 🏔 와인딩+버거 / ☕ 카페 투어 / 📸 사진 찍기 좋은 하루 / 🌲 힐링 / 🚗 크루 나이트런. REVV가 루트+포토스팟+카페+맛집을 하나의 경험으로 엮음. 엔진 일반화(모드별 가중치) 위에 자연스럽게 얹힘.

- **참여형 사진스팟 (2026-07-06, V2 — 해자 후보 1순위):** 지도앱은 맛집은 알지만 "차 세우고 사진 찍기 좋은 곳"은 모른다. 초기엔 OSM/Places 키워드(lookout, belvédère, point de vue…)로 **후보만** 추출 + "검증되지 않은 장소, 안전 정차 가능 시에만" 표시 → 런 종료 후 "오늘 사진 찍은 곳 있어?" 스팟 저장 → 👍 누적 시 Candidate → Verified 승격. 차 사진 특화 기준: 주차 가능 + 배경 + 안전하게 세울 공간. 퀘스트형 루트 검증(2장 확장 모델)과 같은 승격 메커니즘 재사용.

- **Scenic/Night 루트 태그 (2026-07-06, V3 재료):** 현 DB는 와인딩 편향 — 루트 태그를 Driving / Scenic / Night·Mood 3종으로 분리. 풍경 점수 = 물가·고도변화·산/숲/전망대 POI − 공업/주거/고속도로. 야경 점수 = 도시뷰 고도 + 강 건너 스카이라인 + 야간 접근 주차 − 외진 산길·정차 위험. 야경은 루트보다 **정차 스팟** 중심. 자동 추정으로 후보 생성 → 주행 후 질문("풍경 좋았나요? 차 세우기 괜찮았나요?")으로 유저 검증.

- **무료/유료 구분 초안 (2026-07-06):** Free = 엔진 추천 + 기본 루트 3개 + 기록 + 내비 핸드오프 + AI 추천 1회/일. Premium = AI 무제한 + 날씨/노을/카페 포함 플랜 + 취향 학습 + 저장 무제한 + 오프라인 코스 + 크루 플랜. API 비용 아키텍처(2.6장)가 이 경계와 일치.

- **네이밍 재검토 (2026-07-06, 출시 후 — 이름은 REVV로 출시):** 브랜드 철학은 커졌는데 이름은 과거(스포티/속도)에 머문 느낌 — 재검토 가치 있음. 후보군: Cruve / Rovia / Rove / VIASTRA(길+별) / TERRAVIA. 커뮤니티명 분리 아이디어: **Cruvers** (REVV를 즐기는 드라이버들 — Brand/Community/Premium/Event/Media 세계관 구조). 원칙: 자동차 회사처럼 들리는 이름 금지(라이프스타일 브랜드니까), 발음·기억성·도메인·상표·해외 확장성 5기준으로 50~100개 후보를 걸러서 결정. 2~3주 이상 묵히고 상표/도메인/앱스토어 등록 가능성 확인 전 확정 금지.

- **루트 × 음악 매칭 (2026-07-06, Backlog):** 특정 루트에 특정 노래가 나오게 — 드라이브 테마 추천과 결합 시 감성 레이어. / **자동차 행사 추천 (2026-07-06, Backlog):** 루트+행사 결합 — "사람을 지역으로 보내는 플랫폼"이 되면 지역 비즈니스도 고객이 되는 방향.

- **브랜드 필름/시네마틱 (2026-07-06, Backlog):** 마지막 장면은 질주가 아니라 "친구들이랑 웃으면서 서킷에서 하루를 즐기는 장면" — 속도→경험 이동의 신호. V1 출시 후.

- **하드웨어 PTT 트리거 (2026-07-06, 출시 후 묶음):** 크루 워키토키의 핸즈프리 PTT는 3경로. ① **CarPlay** — communication 엔티틀먼트(`com.apple.developer.carplay-communication`) Apple 승인 필요(몇 주). ② **애플워치 컴패니언** — Flutter로 못 만듦(네이티브 watchOS SwiftUI + WatchConnectivity 별도 코드베이스 필요). "손목 트위스트" 커스텀 제스처는 공개 API 없음(AssistiveTouch는 접근성 전용, 후킹 불가). 공식 지원은 **더블탭**(Series 9/Ultra 2+, watchOS 11 주 동작 매핑) 또는 CoreMotion 자체 감지(포그라운드 한정). 현실안 = 워치 앱 + 큰 온스크린 PTT 버튼 + 더블탭 토글. ③ **블루투스 미디어버튼 리매핑**(휠 클립 리모컨) — 다음 주도 가능하나 음악 스킵 버튼 기능 충돌. → v0는 화면 대형 PTT 버튼, 하드웨어 트리거는 출시 후 순차.
