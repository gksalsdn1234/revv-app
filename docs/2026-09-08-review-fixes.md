원격 쓰기 작업은 실제 완료까지 직렬 순서를 유지한다. 읽기와 달리 단순 Future timeout으로 업로드를 버리면 실제 요청이 나중에 끝나 삭제한 데이터를 다시 만들 수 있으므로, 삭제가 진행 중인 상세 업로드의 완료를 기다리는 회귀 테스트를 추가했다. 로컬 저장 성공 표시는 원격 작업을 기다리지 않는다.

## 함께 개선한 흐름

- `AppBootstrap`이 비동기 초기화 전에 화면을 표시한다. 설정/DB 준비 실패에는 재시도를 제공한다. 인증과 사용자별 저장소 준비 순서는 유지했다. 인증 완료 전에 실제 지도나 기록이 전부 준비된다고 주장하지 않는다.
- 첫 위치 조회에서 가까운 루트가 도착하면 한 번만 그 범위를 화면에 맞춘다. 사용자 지도 조작·지역 선택·딥링크 선택을 존중한다. 수동 이동에 “이 지역에서 찾기”가 계속 나타나도록 자동 카메라 이동과 구분했다.
- 미리보기에 “코스 주행 예상 시간 · 시작점 이동 시간 별도”를 한국어/영어/프랑스어로 추가했다. 루트 수와 현재 제공하는 기능은 줄이지 않았다.
- 위치 공급자의 모든 GPS 변경 대신 권한/위치 유무 변화만 Finder가 구독한다. IMU 변화는 계기판 Consumer가 그려서 상위 주행 화면과 지도를 매번 다시 만들지 않는다.
- 리포트 상세 분석과 dynamics 결과는 세션당 한 번 만들고 리플레이/패널 조작 때 재사용한다. 이 변경으로 실기기 배터리나 FPS가 얼마나 좋아졌는지는 측정하지 않았다.
- 저장 실패 시 “나중에 저장”을 제공한다. 복구본 쓰기 성공을 기다린 뒤 이동하며, 그마저 실패하면 명시적 폐기 확인을 보여준다. 사용자가 미룬 짧은 주행도 자동 정리 대상에서 제외한다. 복구본은 원래 루트 메타데이터·주행 경로·샘플을 보관하고 여러 미저장 주행을 차례로 처리한다.
- 시스템 설정에서 돌아오면 위치 권한 상태를 다시 읽는다. 다른 지역을 보고 있을 때 임의로 현재 위치로 이동시키지 않는다.
