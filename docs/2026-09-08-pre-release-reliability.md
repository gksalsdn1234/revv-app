## 1. 저장 실패와 상세 복구

- 저장 상태가 대기/실패/저장 완료/세션 없음으로 구분된다. 실패 시 성공 체크를 표시하지 않고 ‘다시 저장’을 제공한다.
- 로컬 저장이 완료되기 전에는 홈 버튼과 뒤로가기로 리포트를 떠나지 않는다. 재시도 중에는 중복 저장 버튼을 표시하지 않는다.
- 요약과 상세의 로컬 저장 완료를 성공 기준으로 삼는다. 클라우드 업로드는 기존 작업 큐에서 별도로 실행하고, 네트워크나 업로드 대기열 실패가 로컬 저장 실패로 표시되지 않도록 했다. 저장 당시 동의와 실제 업로드 시 동의를 모두 확인한다.
- 실제 주행 시작 시 생성한 UUID v4를 세션·복구 스냅샷·저장에 유지한다. 같은 주행의 재시도나 재복구는 같은 ID를 사용하고, 별개 주행은 새로운 UUID를 쓴다. ID가 없던 이전 스냅샷에는 안정적인 복구 ID를 사용한다.
- 복구도 `saveSession`으로 요약·좌표·텔레메트리·이벤트를 저장한다. 실패하면 복구 창과 원본 스냅샷을 유지하고 그 자리에서 재시도한다. 성공하거나 사용자가 명시적으로 버린 뒤에만 스냅샷을 지운다.
- 종료 순간에도 최종 스냅샷을 남긴다. 복구 파일은 임시 디렉터리에서 앱 지원 디렉터리로 옮겼고 기존 임시 파일 읽기/정리를 지원한다. 기존의 너무 짧은 복구 기록 제외 기준(0.5 km 미만 또는 GPS 10점 미만)은 유지했다.

## 2. 시작·종료 경합과 백그라운드 위치

- 준비 중에는 ‘주행 준비 중’과 취소를 표시한다. 준비 중 취소하면 빈 리포트를 생성하지 않는다.
- 위치 권한, 원본 루트 조회, 위치 추적 준비의 비동기 경계마다 취소/화면 종료를 확인한다. 늦게 도착한 응답이 취소된 주행을 다시 시작하지 못한다.
- 종료 처리를 한 번만 실행하고, 주행 시작 안내는 준비가 끝난 뒤 실행한다. 화면 종료 후 예약된 세션 알림이 이미 해제된 서비스에 접근하지 않도록 했다.
- 수동 주행도 별도의 백그라운드 위치 추적 상태를 갖는다. 자동 기록 대기가 끝나도 수동 주행 중에는 백그라운드 추적이 유지되고, 실제 주행 종료 시 해제된다. iOS의 기존 location background mode를 유지한다.

## 3. 첫 실행 권한과 GPS 상태

- 동시에 요청하는 shell/finder가 `LocationService`의 한 권한 요청 Future를 공유한다. 이미 허용되었거나 설정에서만 변경 가능한 상태에는 불필요한 네이티브 요청을 보내지 않는다.
- 권한 미결정을 ‘꺼짐’으로 표현하지 않는다. 권한/GPS 확인, GPS 확인 실패, 루트 조회 중, 루트 조회 실패를 구분한다.
- 위치 결과 대기도 공유하고, finder 초기 요청은 첫 frame 이후 실행한다. GPS를 기다리는 동안 루트 오류/Retry를 보여주지 않는다.
- 위치 없이도 지역을 검색할 수 있다는 안내와 검색 동작을 제공한다. 이미 선택한 지역의 조회 상태를 기기 GPS 상태가 덮어쓰지 않도록 했다.
